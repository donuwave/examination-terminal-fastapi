## 3. Уведомления

Переключатели в настройках сейчас хранятся только в браузере (`widgets/settings-panel/model/notifications.ts` во фронтенде) и ни на что не влияют.

События:

| Кому | Событие |
|------|---------|
| Студент | пришло приглашение на курс |
| Студент | заявку одобрили или отклонили |
| Студент | закончилась пауза, можно пересдавать |
| Студент | преподаватель дал дополнительную попытку |
| Студент | убрали из курса |
| Преподаватель | новая заявка на курс |
| Преподаватель | у студента закончились попытки, нужно решение |
| Преподаватель | студент принял или отклонил приглашение |

- [ ] Таблица `notification`: `user_id`, `kind`, `payload` (JSON), `created_at`, `read_at`. Один `notify(user, kind, payload)`, который кладёт запись в приложение и, если разрешено, отправляет письмо.
- [ ] Настройки получателя хранить на сервере (таблица или поле профиля), а не в `localStorage`: письма должны их учитывать. Два канала на каждое событие: в приложении и по почте.
- [ ] API: список уведомлений постранично (как `GET /test-progress/`), число непрочитанных, «прочитано» для одного и для всех.
- [ ] Планировщик: задача «пауза закончилась». Время известно заранее (`next_attempt_at` в состоянии теста), поэтому задача проверяет завершённые попытки и шлёт уведомление один раз. Нужен признак «уже уведомили».
- [ ] Фронт: колокольчик в боковом меню со счётчиком, страница или выпадающий список уведомлений, переход к нужному курсу или тесту по клику. Переключатели в настройках подключить к серверу.
- [ ] В письмах ссылка «Отключить такие письма», которая ведёт в настройки.
- [ ] Тесты: событие создаёт уведомление, настройка «выкл» отключает письмо, но не запись в приложении (или наоборот, решить заранее), пауза уведомляет ровно один раз.
