# Экзаменационный терминал: бэкенд

API платформы курсов с тестами. Преподаватели создают курсы, разделы, материалы и тесты, студенты записываются, проходят тесты с таймером и видят свой прогресс.

**Фронтенд:** [examination-terminal-vue](https://github.com/donuwave/examination-terminal-vue)

FastAPI, SQLAlchemy 2 (async), PostgreSQL, Alembic, JWT, pytest.

## Что умеет

- **Курсы и разделы.** В разделе материалы по порядку и тест в конце. Следующий раздел открывается, когда сданы тесты предыдущего. Дедлайнов нет.
- **Запись на курс.** Курс бывает свободным (студент записывается сам) или по заявке. Преподаватель не добавляет студентов напрямую: он приглашает по почте, студент принимает или отклоняет.
- **Тесты.** Вопросы трёх типов: один верный ответ, несколько верных, текстовый ответ. Проходной процент, число попыток и пауза между ними задаёт преподаватель. После провала правильные ответы скрыты и открываются, когда тест сдан или попытки закончились. Преподаватель решает судьбу студента без попыток: дать ещё одну или убрать из курса.
- **Попытки.** Просроченные попытки закрываются временем окончания. Список попыток постраничный.
- **Аналитика** для преподавателя: прогресс студентов, разделов и тестов, разбор вопросов, распределение результатов.
- **Уведомления** в приложении (восемь событий, настройки на сервере) и фоновая задача «пауза закончилась».
- **Профили** других пользователей по правилам доступа, сертификат о прохождении курса.
- **Безопасность.** JWT, роли, проверка автора теста, ограничение попыток входа и регистрации, отзыв токенов после смены пароля.
- **Восстановление пароля** по коду из письма: шестизначный код на 15 минут, пять попыток, ограничение запросов по почте и по адресу, ответ одинаков для любой почты.

## Быстрый старт

Нужны Python 3.12+, [Poetry](https://python-poetry.org), Docker и OpenSSL.

```bash
poetry install
docker compose up -d db                  # PostgreSQL на порту 5437
./scripts/generate-keys.sh               # ключи для подписи JWT, в git не попадают
cp .env.example .env.dev                 # адрес базы
export ENV=dev
alembic upgrade head                     # схема и справочники (роли, типы курсов)
uvicorn main:app --reload
```

API работает на http://localhost:8000, документация на http://localhost:8000/docs.

Переменные окружения (в `.env.dev`, `.env.prod`):

| Переменная     | Назначение                                                        |
|----------------|-------------------------------------------------------------------|
| `DATABASE_URL` | Адрес базы, `postgresql+asyncpg://user:pass@host:port/db`          |
| `ENV`          | `dev` или `prod`: какой `.env.*` читать                           |
| `CORS_ORIGINS` | Адреса сайтов через запятую, которым разрешён доступ (необязательно) |
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD` | SMTP-сервер для писем. Без `MAIL_HOST` письма пишутся в лог сервера |
| `MAIL_FROM`, `MAIL_FROM_NAME`, `MAIL_SECURITY` | Отправитель и защита соединения: `starttls` (587), `ssl` (465) или `none` |

## Тесты

Тесты идут в отдельной базе и отказываются запускаться, если её имя не начинается с `test`. Рабочая база им недоступна.

```bash
docker compose -f docker-compose.test.yml up -d      # база на порту 5438
poetry run pytest -q
```

Другая база: переменная `TEST_DATABASE_URL`. Схема пересоздаётся перед каждым тестом.

## Устройство

```
main.py             приложение, CORS, планировщик
scheduler.py        фоновые задачи (пауза после попытки, чистка уведомлений)
core/               настройки, модели SQLAlchemy, ограничение частоты запросов
api_v1/             модули API: у каждого views, crud, schemas
  auth/ profile/ role/
  course/ course_section/ course_material/ course_request/ course_test/ questions/
  test_progress/    попытки и правила прохождения (rules.py, grading.py)
  analytics/ notification/ certificate/
alembic/            миграции
tests/              pytest
```

Правила прохождения теста собраны в `api_v1/test_progress/rules.py` (состояния «новый», «идёт», «сдан», «пауза», «ждёт решения»), проверка ответов всех типов в `grading.py`.

## Продакшен

```bash
cp .env.prod.example .env.prod        # заполнить пароль базы
./scripts/generate-keys.sh
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

Поднимутся PostgreSQL и API (миграции применяются при старте). Как отдавать фронтенд, решается отдельно. Приложение запускается с `--proxy-headers`: если перед ним стоит прокси, лимиты входа считаются по настоящему адресу клиента.

Лимиты запросов хранятся в памяти процесса: для нескольких экземпляров приложения их нужно вынести в общее хранилище.
